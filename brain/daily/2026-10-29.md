# Daily Change Log: 2026-10-29

## Context & Objectives
The user verified their VPS terminal and discovered that PM2 was not installed globally (`⚠️ PM2 not found globally! Falling back to npx pm2...`). Additionally, in automated non-interactive CI, `npx pm2` fails without `-y` because it attempts to prompt for package confirmation (`Need to install the following packages: pm2 Ok to proceed? (y)`).

## Root Causes Identified
1. **PM2 Not Installed on VPS**: The VPS environment did not have `pm2` installed globally via `npm install -g pm2`.
2. **Interactive `npx` Prompt**: The fallback `PM2_CMD="npx pm2"` lacked the non-interactive auto-confirm `-y` flag, causing the process to fail with exit code 1 inside GitHub Actions.

## Changes Implemented
1. **Automated Global PM2 Installation**:
   - In `.github/workflows/Deploy.yaml`, added an automatic check:
     ```bash
     if ! command -v pm2 >/dev/null 2>&1; then
       echo "⚠️ PM2 not found globally! Installing PM2 globally on VPS..."
       npm install -g pm2 || true
     fi
     ```
2. **Non-Interactive NPX Fallback**:
   - Updated the fallback to use `npx -y pm2` to ensure zero-prompt execution if global permissions fail.
3. **Streamlined Zero-Downtime Reload & Accurate App Directory Discovery**:
   - Replaced fragile `if describe` logic with clean, safe reload: `pm2 reload "$APP_NAME" --update-env 2>/dev/null || pm2 reload ecosystem.config.cjs --env production 2>/dev/null || pm2 start ...`.
   - Updated directory detection loop to dynamically discover the actual repository root containing `server.js` and `.git` (resolves disparity between `$HOME/first` and nested `./first/first`).
